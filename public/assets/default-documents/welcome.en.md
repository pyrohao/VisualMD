# Welcome to VisualMD

[VisualMD](https://github.com/pyrohao/VisualMD) is a free, online, and open-source Markdown visual workbench. It integrates **Markdown writing, structure organization, real-time preview, AI collaboration, and Git version control** into a single browser workflow, suitable for technical documents, product solutions, knowledge bases, prompt documents, and study notes—content requiring long-term iteration.

```text 
VisualMD = Markdown Editor + Document Structure Canvas + AI Collaboration Panel + Git Workspace
```

## Quick Overview

- **Organize the structure first, then add content**: Markdown headings can be directly converted into an editable tree structure, suitable for planning long documents.
- **Multi-view联动 (synchronous operation) of the same content:** Source code, preview, Live, Split, and Prototype views work synchronously around the same Markdown document.
- **AI is no longer an external chat window:** You can directly interpret, rewrite, expand, and polish based on the current document fragment.
- **Built-in Git workflow:** Supports connection to GitHub/Gitee for direct browsing, editing, committing, and conflict resolution.
- **No locked private format:** The underlying standard Markdown remains, and the document can still be exported for use in other tools.

## Quick Start

1. Create a new Markdown document or import an existing Markdown.
2. First, use `Markdown → Tree` to expand the heading structure into a tree, adjusting the chapter order and hierarchy.
3. When polishing, select the text and press **Ctrl + L** to send the fragment into the AI ​​context.
4. When previewing, switch to the `Live`, `Split`, or `Prototype` view to see the effect.
5. If you have already configured Git, you can continue committing, staging, syncing, and handling conflicts.

## Common Use Cases

### Writing Long Documents or Knowledge Bases

- First, plan the entire document using a mind map or tree structure, then return to the main text and fill in the details paragraph by paragraph.
- When the structure changes frequently, prioritize adjustments in the structure view; this is more efficient than directly cutting and pasting from the source code.
- If the document will eventually be subject to version control, it is recommended to use a clear heading hierarchy from the beginning.

### Using AI for Explanation, Rewriting, and Continuation

1. Select a section of content in the editing or preview area.
2. Press **Ctrl + L**.
3. The selection will enter the AI ​​dialogue context.
4. Enter your request, for example:
- "Explain this content"
- "Change to a more formal tone"
- "Expand into a product description"
- "Add a summary section"

AI is better used as a "document accelerator" than a standalone chat window detached from the context.

### Managing Markdown Assets with Git

- Browse the repository directory tree online.
- Directly edit Markdown files within the repository.
- Text and image assets can be staged and committed in batches.
- In case of conflicts, conflicts are resolved first before refreshing or committing.

### Image and Resource Handling

#### Local Documents

- Supports direct image pasting.
- The system maintains resource files for the local working directory and adds image links to the Markdown.
- When exporting a single local document, if it references local resources, the system will automatically export it as a `.md` file or a compressed archive containing resources.

#### Git Documentation

- Git documentation also supports pasting and referencing images.
- However, the local resource path and the Git repository resources are not from the same source.

#### Important Note

If a local Markdown document references local resource images, even if you add the document to Git, the images themselves will not be automatically added to the repository. To commit such images, ensure they have already been added to the repository's resource path according to the Git workflow.

## Git Configuration Guide

VisualMD works out of the box by default; if you want to connect to a repository and use features such as commits, synchronization, and conflict handling, you'll need to prepare a **PAT/Token** first.

### Currently Supported Platforms

- `GitHub`
- `Gitee`

### Required in Git Settings

- `Provider`: Select `GitHub` or `Gitee`
- `Token`: Your PAT/access token
- `owner/group`: Username, organization name, or namespace
- `repo`: Repository name
- `branch`: Branch name, e.g., `main`

### GitHub Configuration

It is recommended to use fine-grained tokens instead of classic tokens: **Fine-grained personal access token**

1. Open [github-personal-access-tokens](https://github.com/settings/personal-access-tokens)
2. Go to `Fine-grained tokens`
3. Create a new token
4. Select the account or organization you want to access, and the target repository
5. Assign read and write permissions to the `Contents` of the target repository

If your organization has restrictions on tokens... Additional restrictions apply, and administrator permission may be required.

### Gitee Configuration Method

1. Log in to Gitee
2. Open the token page in your personal settings
3. Create a new access token
4. Assign it permissions that cover repository access and push functionality

Recommended entry point: [gitee-personal_access_tokens](https://gitee.com/profile/personal_access_tokens)

It is recommended to at least ensure:

- Ability to read the target repository's content
- Ability to write or push content to the target repository

### First Checks When Connection Fails

If a repository connection fails, the most common cause is not a program problem, but a configuration problem:

1. Is the `Provider` selected correctly? `GitHub` and `Gitee` cannot be used interchangeably.
2. Is the `Token` entered incorrectly, expired, or has insufficient permissions?
3. Are `owner/group`, `repo`, and `branch` misspelled?
4. Does the current token actually have the right to access the repository? ### Git Token Security Considerations

- Grant only the minimum necessary permissions; avoid granting full permissions for convenience.
- Only authorize necessary repositories; do not grant permissions to all private repositories by default.
- If you suspect a leak, immediately revoke the old token and regenerate it in the GitHub/Gitee backend.
- The current project stores the token locally in the browser and performs local encryption/obfuscation; this reduces the risk of accidental exposure, but it is not equivalent to server-side key escrow. Therefore, you should still avoid storing high-privilege tokens on untrusted devices for extended periods.

## AI Configuration Guide

VisualMD's AI capabilities work using a "built-in model channel" approach. To enable AI, you need to prepare and fill in the following in the AI ​​settings panel:

- `API Base URL`
- `API Key`
- `Model`

### Currently Supported

- `OpenAI-compatible`
- `Anthropic-compatible`

Multiple preset channels are built-in, such as OpenAI, Anthropic, OpenRouter, SiliconFlow, Tongyi, Volcano Ark, and Zhipu. You can also manually fill in custom compatible interfaces.

### AI Configuration Method

1. Open the AI ​​settings panel
2. Select a preset provider or create a custom provider
3. Fill in the `API Base URL`
4. Fill in the `API Key`
5. Select or refresh the `Model`
6. Click `Test Connection`

If the model list can be read automatically, you can also fill in the `API Base URL` and `API Key` first, and then refresh the model list.

### AI Key Security Precautions

- Prioritize using `API Keys` with quota control or free ones.
- If you suspect a key leak, immediately revoke the old key and regenerate it on the corresponding platform.
- If you are very concerned about the risk of key exposure, a more secure solution is to forward the key through your own backend or proxy layer, rather than directly entering the highly sensitive key into the frontend page.
- The current project will store the AI ​​Key locally in the browser and perform local encryption/obfuscation; this is suitable for personal use with self-provided keys, but should not be considered an enterprise-level key vault.

## Prototype Quick Reference

Prototype mode is suitable for quickly adding a sense of page layout and interactivity to existing Markdown content. The core rule is only one sentence:

**Write Markdown normally, and insert the `@proto` directive where you need controls.** 

### Commonly Supported Directives

- `@proto input label="" placeholder="" type=""`: Single-line input box
- `@proto textarea label="" placeholder=""`: Multi-line input box
- `@proto button text="" action="" intent="primary|secondary" goto="" target="" dialog=""`: Button
- `@proto toggle label="" checked="true|false"`: Toggle
- `@proto tabs items="A|B|C"`: Tabs
- `@proto card title="" description=""` or `desc=""`: Information card
- `@proto stat label="" value=""`: Statistics block
- `@proto note text=""` or `content=""`: Note block

### A Minimal Example

```md
### Login Page

@proto card title="Welcome Back" description="Continue accessing the workspace after logging in"
@proto input label="email" placeholder="name@example.com" type="email"
@proto input label="password" placeholder="Please enter your password" type="password"
@proto toggle label="Remember me" checked="true"
@proto button text="Log in now" action="login" intent="primary"

```

In addition to these directives, Prototype mode also supports regular Markdown content, including paragraphs, quotes, lists, task lists, tables, fenced code blocks, as well as inline bold, italics, code, links, and images.

## Other Useful Tips

- The welcome document is only automatically created once when the workspace is first loaded; subsequent deletions will not automatically restore it.
- If you mainly do structural organization, prioritize using mind map mode; if you want to create presentations or interactive sketches, prioritize switching to Prototype mode.
- If you see conflict warnings in Git mode, resolve the conflicts first, then refresh the repository or continue committing.
- If the images appear normal in the preview but are missing in Git, it's usually not a rendering issue, but rather that the resources haven't actually been added to the repository.
- Cloud, Git, and AI are all optional extensions; if you only want to write Markdown locally, you can also use the basic editing capabilities separately.
