# Capability Domain Overview
## Purpose
- Explain when this capability should be activated as a supporting aid.

## Core Principles
1. Layer the problem space (System / Subsystem / Component)
2. Stay user-driven (prioritize real user feedback)
3. Evaluate through a cost-benefit lens (use ROI as the primary measure)

## Usage Guidance
- Apply this lens to step 2 of a process-oriented skill: Design Thinking
- Example: give `frontend-design` a tradeoff matrix for "visual impact vs accessibility"
